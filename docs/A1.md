## 하드웨어와 통신

### 시리얼·MCU·IMU

특정 시험 시점에는 `/dev/myserial -> /dev/ttyUSB0`, `/edition=3.6`, 배터리 약 10.2V, `/imu/data_raw` 발행과 `Serial Opened` 로그가 확인됐습니다. 이 값은 모든 A1의 고정 매핑이 아닙니다.

```bash
readlink -f /dev/myserial
ls -l /dev/serial/by-id/
ros2 topic echo /edition --once
ros2 topic echo /voltage --once
ros2 topic echo /imu/data_raw --once
```

### 한쪽 바퀴만 회전

보드 통신이 보이더라도 모터·배선·출력 채널·기계적 걸림은 별도로 진단해야 합니다. 기록된 사례는 최종 수리 원인이 확인되지 않았습니다.

1. 차량을 정지하고 바퀴를 지면에서 분리합니다.
2. 배터리와 왼쪽 모터·커넥터·배선을 확인합니다.
3. `/cmd_vel` 연결, 전압, IMU, 시리얼 경로를 확인합니다.
4. 모터 이상을 캘리브레이션 값으로 보정하려 하지 않습니다.

## 카메라: NUWA HP60C

HP60C는 일반 UVC 카메라처럼 항상 `/dev/video0`로 나타난다고 가정할 수 없습니다. `lsusb`에 장치가 보여도 `ascamera` 전용 SDK 상태와 ROS 이미지 토픽을 별도로 확인합니다.

```bash
lsusb
v4l2-ctl --list-devices
ros2 pkg executables ascamera
ros2 launch ascamera hp60c.launch.py
ros2 topic list -t
```

- `uvc_open: Busy`, `ret -82`: 중복 카메라 노드와 장치 점유, 케이블·허브·전원, SDK 로그를 순서대로 확인합니다. 최종 원인은 미확정입니다.
- `Select timeout`: UVC 설정 문제와 HP60C SDK 인식 문제를 분리합니다. 캘리브레이션 파일 부재를 프레임 미수신의 단일 원인으로 단정하지 않습니다.

## LiDAR와 RViz

`/scan` 발행 여부와 RViz 표시 여부는 다른 문제입니다. 설치된 실물 모델과 드라이버를 확인한 뒤 토픽 주기, `frame_id`, TF, RViz Fixed Frame 순으로 점검합니다.

```bash
ros2 topic hz /scan
ros2 topic echo /scan --once
ros2 run tf2_ros tf2_echo base_link laser
```

지식베이스에는 과거 launch 명령이 기록되어 있지만, `RPLIDAR_TYPE=c1` 같은 인자는 실물 T-MINI Plus와 일치하는지 먼저 검증해야 합니다.

## 모터·조향과 캘리브레이션

- 정지 명령은 구동 정지와 조향 중앙 복귀를 동시에 보장하지 않을 수 있습니다. 실제 `cmd_vel_callback`과 `set_car_motion` 매핑을 확인합니다.
- 선속도 보정은 안정적인 odom/TF와 안전한 직선 공간이 확보된 뒤 수행합니다.
- Ackermann 차량의 회전 보정에서 제자리 회전 가정을 사용하지 않습니다.
- `transform not ready` 상태에서 scale 값을 임의 조정하지 않습니다.
- `NameError: publish`는 원본 패키지를 직접 덮어쓰지 말고 복제본에서 호출 구문을 확인해야 하는 미해결 코드 오류입니다.

## 안전 범위

이 문서는 실차 명령을 자동 실행하지 않습니다. 모터·조향 시험은 [공통 안전 절차](TROUBLESHOOTING.md#안전-우선순위)를 먼저 적용하세요.
